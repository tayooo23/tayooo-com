個人環境の構成図（2026年11月版）

個人で運用している環境の棚卸し。物理マシンは自宅の Raspberry Pi 1台だけで、あとはクラウドの VM と Tailscale でつないでいる。ポート開放はゼロで、接続は原則すべて Tailscale 経由。重い作業はクラウド側に逃がして、自宅は静かに回す、という分担である。

構成図

つなぎ方

接続は原則すべて Tailscale 経由に寄せている。OCI VM のリモートデスクトップ（XRDP）も 3389 番をインターネットに公開せず、Tailscale の内側からだけ届くようにした。自宅側は Raspberry Pi が LAN（192.168.0.0/24）のサブネットルートを広告しているので、外出先の iPhone からも自宅の機器に「同じ LAN にいる」感覚で届く。

AIアシスタント（Muse）にも作業させるため、Pi と VM には専用ユーザーを作って鍵認証だけを許可している。sudo は付けていない。設定変更が要る作業は「スクリプトを用意してもらって、自分が1行だけ実行する」分担にしていて、これは思いのほか安全で速い。

AIに触らせるデスクトップ

OCI VM の中には、自分用とは別に、Muse 専用の仮想デスクトップも用意してある。TigerVNC で 1280×800 の Xfce 画面を作り、Chrome はリモートデバッグ（CDP）を有効にしてある。Muse はこの Chrome を CDP 経由で操作するので、画面のスクリーンショットを見ながらではなく、ページの構造（DOM）を直接読んで、クリックや入力、フォーム送信まで実行できる。デスクトップ自体も Tailscale の内側からしか届かない場所に置いてある。

どんな時に使うかというと、普段の作業は Muse 側のブラウザで足りていて、このデスクトップの出番は限られる。具体的には次のような「切り札」用途だ。

  • 懸賞応募などで、通常の自動ブラウザがボット判定で弾かれた案件の再挑戦
  • 日本の IP でないと開けない・応募できないサイトでの作業
  • ログイン状態を保持したまま、同じブラウザで繰り返し作業したいとき

メリットは3つ。まず、国内 IP ＋ 実ブラウザなので、クラウド側の自動ブラウザより弾かれにくい。次に、CDP で構造を直接操作できるため、スクリーンショット駆動の操作より速く、AI 側のトークン消費も大幅に少ない（これは実際に比較して確認した）。最後に、ブラウザのプロファイルが残るので、ログイン状態や作業の続きを保持できる。

デメリットもある。用意と維持にひと手間かかる（VNC の起動・停止は手動、ログインが切れたら GUI で再ログインが要る）。何でもできるわけではなく、画像認証のような「見て解く」操作は苦手で、最後は人間の出番になる。あと VM が arm64 なので、x86 向けのソフトは QEMU 経由のような工夫が要る（moomoo の OpenD がまさにその例）。

効率の実感としては、「普段は眠っている保険」という位置づけが正直なところだ。出番自体は少ない。ただ、弾かれて終わりだった案件を拾えるかどうかは大きくて、その一点で置いておく価値があると思っている。

監視

監視は Pi 上の Zabbix に集約。対象は Pi 本体、ルーター、デスクトップ、OCI VM、このサイトの5つ。ついでに天気・防災のダッシュボード（地震情報や警報）と、Muse の使用率グラフも同じ画面に置いている。通知は異常のときだけ来る設定で、正常な日は何も届かない。静かなのが正解、という運用である。

締め

物理サーバーはラズパイ1台に集約できたので、電気代も場所も取らない。デスクトップ環境が要る作業は OCI の VM、監視と出入口は Pi、サイトは Cloudflare。境界線を引いて、あとは Tailscale でつなぐ——今のところ、この形が一番落ち着いている。
